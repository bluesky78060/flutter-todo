# 실기기 확인 가이드 — DTA-3-1 (캘린더 동기화) + DTA-3-4 (범위 일정)

- 작성일: 2026-08-21
- **여기까지의 검증은 전부 코드 레벨이다.** 실제 Google Calendar 에 일정이 등록되는 것을
  아직 아무도 보지 못했다. 이 문서의 목적은 그것을 확인하는 것이다.

---

## 0단계 — Supabase SQL 2개 (필수 선행)

Supabase 대시보드 > SQL Editor 에서 실행한다.

```sql
ALTER TABLE todos ADD COLUMN IF NOT EXISTS google_event_id TEXT;
ALTER TABLE todos ADD COLUMN IF NOT EXISTS start_date TIMESTAMPTZ;
```

확인:
```sql
SELECT column_name FROM information_schema.columns
WHERE table_name = 'todos'
  AND column_name IN ('google_event_id', 'start_date');
```
**두 줄**이 나와야 한다.

### 안 돌리면 어떻게 되나

| 컬럼 | 미실행 시 |
|---|---|
| `google_event_id` | 등록은 되지만 **중복 방지가 동작하지 않는다** (두 번 누르면 중복) |
| `start_date` | **범위 일정 생성만 실패**한다 |

**둘 다 기존 기능(할 일 생성·수정·삭제·알림)에는 영향이 없다.** 일부러 그렇게 만들었다.

## 1단계 — 앱 실행

```bash
flutter run -d chrome          # 또는 실기기
```

로그를 볼 수 있게 터미널을 열어 둔다. 문제가 생기면 `📅 GoogleCalendar:` 로 시작하는 줄이 단서다.

---

## 2단계 — 테스트 데이터 4건

| 이름 | 설정 | 확인 목적 |
|---|---|---|
| **A** | 마감일 O, **알림 없음** | 종일 이벤트 버그(DTA-3-1 핵심) |
| **B** | 마감일 O, 알림 O | 시간 지정 이벤트가 그대로인지 |
| **C** | 마감일 O, **완료 처리** | 동기화 대상에서 빠지는지 |
| **D** | **기간 8/21~8/25**, 알림 O | 범위 + 알림 조합(DTA-3-4 핵심) |

---

## 3단계 — 범위 일정 (DTA-3-4)

- [ ] 폼에 **"기간으로 설정"** 토글이 보이는가
- [ ] 토글을 켜면 **기간 선택기**가 뜨는가
- [ ] 선택 후 폼에 `2025-08-21 ~ 2025-08-25` 로 보이는가
- [ ] **목록**에 기간이 보이는가 — `(하루 종일)` 이 **두 번 나오면 안 된다**
- [ ] **상세**를 열면 라벨이 "기간" 이고 값이 `8/21 ~ 8/25` 인가
- [ ] **캘린더**에서 8/21, 8/23, 8/25 를 각각 눌렀을 때 **전부** D 가 보이는가
      (8/20, 8/26 에는 안 보여야 한다)

### 범위 해제 — 가장 취약했던 지점

- [ ] D 를 열어 토글을 **끄고 저장**
- [ ] 목록에서 하루짜리로 바뀌는가
- [ ] **앱을 완전히 종료했다 다시 켜도** 하루짜리인가
      → 여기서 범위가 되살아나면 `start_date` SQL 이 안 돌아간 것이다

### 반복 조합 차단

- [ ] 반복 일정을 하나 만든다 (예: 매주)
- [ ] 생성된 **인스턴스**를 열어 "기간으로 설정" 을 켜 본다
- [ ] **"반복 일정에는 기간을 설정할 수 없습니다"** 가 뜨고 켜지지 않는가
      → 이게 코드 리뷰에서 잡힌 CRITICAL 이다. 켜지면 안 된다
- [ ] 반대로, 기간이 켜진 상태에서 반복 설정을 눌러도 막히는가

## 4단계 — Google Calendar 동기화 (DTA-3-1)

설정 > Google Calendar > 연결 후:

- [ ] 연결 상태와 계정 이메일이 뜨는가
- [ ] **"할 일을 캘린더에 동기화"** 실행
- [ ] 스낵바에 **결과 숫자**가 뜨는가 (예: "할 일 3개를 캘린더에 등록했습니다")
      → 예전에는 "동기화 중" 만 뜨고 끝났다

캘린더에서 확인:

- [ ] **A 가 종일 이벤트로 딱 하루만** 차지하는가 ← DTA-3-1 핵심
- [ ] A 가 **이틀에 걸쳐 있지 않은가** (그렇다면 `end.date` 를 하루 더 더한 것)
- [ ] B 가 알림 시각부터 **1시간**짜리인가
- [ ] **C(완료)는 등록되지 않았는가**
- [ ] **D 가 8/21~8/25 5일에 걸쳐 있는가** ← DTA-3-4 핵심
      → **하루짜리나 1시간짜리로 뜨면 실패다.** 알림이 있어도 종일로 나와야 한다

### 중복 방지

- [ ] 동기화를 **한 번 더** 실행
- [ ] 스낵바 숫자가 1회차와 같은가
- [ ] 캘린더에 **같은 일정이 두 개 생기지 않았는가** ← 핵심
- [ ] A 의 제목을 앱에서 바꾸고 다시 동기화 → 캘린더의 **기존 이벤트 제목이 바뀌는가**
      (새 이벤트가 생기면 update 경로가 안 도는 것)

### 폴백

- [ ] 캘린더에서 A 를 **직접 삭제** → 앱에서 다시 동기화 → **A 가 다시 생기는가**

### 실패 표시

- [ ] 연결 해제 후 동기화 → "Google Calendar에 연결되어 있지 않습니다"
- [ ] 대상이 없는 상태로 동기화 → "등록할 할 일이 없습니다"

---

## 5단계 — 회귀 확인 (건드리지 않았어야 하는 것)

- [ ] 할 일 **생성 / 수정 / 삭제**가 정상인가
- [ ] 알림이 정상 예약되는가
- [ ] 기존 하루짜리 할 일이 캘린더에서 **하루만** 차지하는가
- [ ] 반복 일정 생성·편집이 정상인가

---

## 알려진 미해결 (이번에 안 고침)

여기 해당하는 건 **버그 신고가 아니라 예정된 작업**이다.

| 현상 | 티켓 |
|---|---|
| 우선순위를 바꿔도 재조회하면 medium 으로 돌아감 | `DTA-3-2` |
| 완료·삭제해도 캘린더에 이벤트가 남음 | `DTA-3-3` |
| 반복을 "이후 모두" 로 편집하면 캘린더에 중복 | `DTA-3-5` |
| 기간 중인 일정이 목록에서 **종료일 기준으로 정렬**됨 | 미해결 기록 |
| 홈 위젯 · Windows 위젯에 기간이 반영되지 않음 | 범위 밖 (합의) |
| 내보내기가 기간을 종료일 한 칸으로만 씀 | 범위 밖 |
