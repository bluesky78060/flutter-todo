# 수동 확인 체크리스트 — DTA-3-1 Google Calendar 동기화

- 작성일: 2026-08-21
- 대상: `DTA-3-1`
- **자동 검증 불가 사유**: OAuth 로그인과 실제 Google Calendar 쓰기가 필요하다.
  단위 테스트로 못박은 것은 **이벤트 객체 구성**까지다.

## 0. 선행 — Supabase 컬럼 추가 (필수)

Supabase 대시보드 > SQL Editor 에서 실행:

```sql
ALTER TABLE todos ADD COLUMN IF NOT EXISTS google_event_id TEXT;
```

**돌리지 않으면**: 일정 등록은 되지만 이벤트 ID가 저장되지 않아
**두 번 동기화하면 중복이 생긴다.** 나머지 기능(할 일 생성/수정/삭제)은 영향 없다.

확인:
```sql
SELECT column_name FROM information_schema.columns
WHERE table_name = 'todos' AND column_name = 'google_event_id';
```
한 줄이 나와야 한다.

## 1. 준비

- [ ] 앱 실행: `flutter run -d chrome` (또는 실기기)
- [ ] 설정 > Google Calendar > 연결. 연결 상태와 계정 이메일이 뜨는지 확인
- [ ] 테스트용 할 일 3개 생성
  - A: 마감일 있음 + **알림 시간 없음** ← **이번 버그의 핵심 대상**
  - B: 마감일 있음 + 알림 시간 있음
  - C: 마감일 있음 + **완료 처리**

## 2. 핵심 확인 — 이번 버그가 실제로 고쳐졌는가

- [ ] 설정 > Google Calendar > **"할 일을 캘린더에 동기화"** 실행
- [ ] 스낵바에 **결과 숫자**가 뜨는가 (예: "할 일 2개를 캘린더에 등록했습니다")
      → 예전에는 "동기화 중"만 뜨고 끝났다
- [ ] Google Calendar 에서 **A가 종일 이벤트로, 딱 하루만** 차지하는가
      → **이게 이번 수정의 핵심.** 예전에는 아예 등록되지 않았다
- [ ] A가 **이틀에 걸쳐 있지 않은가** (그렇다면 `end.date`를 하루 더 더한 것)
- [ ] B가 알림 시각부터 **1시간짜리**로 뜨는가
- [ ] **C(완료)는 등록되지 않았는가** → 동기화 대상은 미완료만이다

## 3. 중복 방지 확인

- [ ] 동기화를 **한 번 더** 실행
- [ ] 스낵바 숫자가 1회차와 같은가
- [ ] Google Calendar 에 **같은 일정이 두 개 생기지 않았는가** ← 핵심
- [ ] A의 제목을 앱에서 바꾼 뒤 다시 동기화 → 캘린더의 **기존 이벤트 제목이 바뀌는가**
      (새 이벤트가 추가되면 update 경로가 동작하지 않는 것)

## 4. 폴백 확인

- [ ] Google Calendar 에서 A 이벤트를 **직접 삭제**
- [ ] 앱에서 다시 동기화
- [ ] A가 **다시 생성**되는가 → update 404 시 insert 폴백이 동작하는 것

## 5. 실패 표시 확인

- [ ] 설정에서 Google Calendar **연결 해제** 후 동기화 시도
- [ ] "Google Calendar에 연결되어 있지 않습니다" 가 뜨는가
- [ ] 마감일 있는 미완료 할 일이 하나도 없는 상태에서 동기화
- [ ] "등록할 할 일이 없습니다" 가 뜨는가

## 6. 회귀 확인 (건드리지 않았어야 하는 것)

- [ ] 할 일 생성 / 수정 / 삭제가 정상 동작하는가
      → `google_event_id` 를 일반 `updateTodo` payload 에서 **뺀** 이유가 이것이다.
        SQL 을 안 돌린 상태에서도 여기가 깨지면 안 된다
- [ ] 알림이 정상 예약되는가
